### 2.2 Chuẩn hoá query

- Server: bỏ khoảng trắng đầu; ký tự đầu `#` → `scope=tag`, bỏ `#`, lấy token đầu. `q` → `textnorm.NormalizeQuery` (item/all) hoặc `NormalizeTagQuery` (tag) = `qn`. `qa = immutable_unaccent(qn)` tính **trong SQL** (một nguồn sự thật với cột generated).

- Server trả `match ∈ {prefix, prefix_folded, fuzzy}` mỗi hàng; client highlight bằng `splitMarkedPrefix` (prefix), biến thể fold `features/omnibox/suggest/fold.ts` (NFD, bỏ `\p{Mn}`, `đ/Đ→d`), `fuzzy` → nhãn "gần đúng" không `<mark>`. Highlight chỉ là text node.

### 2.3 Kênh và ranking lexical (D8; không RRF, không weighted sum)

Mỗi corpus một câu (`internal/db/queries/search_lexical.sql`), hai goroutine song song, mỗi câu read tx riêng với `SET LOCAL statement_timeout = '50ms'`, `pg_trgm.similarity_threshold = 0.35`, `pg_trgm.word_similarity_threshold = 0.5` (giá trị khởi đầu; chỉ đổi kèm số đo của Task 23):

```sql
-- SearchItemsLexical: $1 user_id, $2 qn, $3 q_prefix (escaped qn || '%'), $4 fuzzy bool, $5 limit
WITH q AS (SELECT $2::text AS qn, immutable_unaccent($2::text) AS qa)
SELECT i.id, i.name, i.entry_count, i.last_used_at, i.created_at,
       CASE WHEN i.name_normalized LIKE $3 ESCAPE '\' THEN 3
            WHEN i.name_unaccent LIKE immutable_unaccent($3) ESCAPE '\' THEN 2
            ELSE 1 END AS tier,
       round(GREATEST(similarity(i.name_unaccent, q.qa),
                      word_similarity(q.qa, i.name_unaccent))::numeric, 2) AS score
FROM item i, q
WHERE i.user_id = $1 AND i.deleted_at IS NULL
  AND (i.name_normalized LIKE $3 ESCAPE '\'
       OR i.name_unaccent LIKE immutable_unaccent($3) ESCAPE '\'
       OR ($4 AND (i.name_unaccent % q.qa OR q.qa <% i.name_unaccent)))
ORDER BY tier DESC, score DESC, i.last_used_at DESC, i.entry_count DESC, i.id ASC
LIMIT $5;
```

- Tag cùng hình trên `normalized`/`tag_unaccent`, `count = item_count`. Recent: `last_used_at DESC, id DESC` (khớp `*_user_recent`; SPEC §6.4 ghi `id ASC` → Task 1 sửa).
- Tier: prefix đúng dấu 3 > prefix bỏ dấu 2 > fuzzy 1 (`score ≥ 0.35`); trong tier `score` (làm tròn 2 chữ số) rồi `last_used_at DESC`, `count DESC`, `id ASC`. Recency/count chỉ phá hoà; không so điểm giữa item và tag.
- Corpus item = **chỉ `name`** (hint vào input semantic) — OQ-4. Typo chỉ hứa trên từ ≥ 5 ký tự (`pasword`→`password` ≈ 0.70, `wiifi`→`wifi`); `wfii` (≈ 0.11) không bắt được — OQ-5, Task 1 đổi ví dụ §6.2 l.931.
- `LIMIT` = trần corpus theo quota + 1 (biết `has_more`). Nhánh quá 50 ms → rỗng + `lexical_partial: ["item"|"tag"]`, client không cache, không báo lỗi.
- Chip tag cho item hit: `ListTagRefsForItems(user_id, item_ids[])` ≤ 3 `TagRef` sống/item theo `display` + `tag_total`.

### 2.4 Quota theo `limit` (OQ-3, OQ-9 — quyết định advisor-dec-244)

Quota chỉ phụ thuộc `(scope, limit, mode)`, **không** phụ thuộc semantic bật/tắt/sẵn sàng; `near_reserve` luôn để dành (trống khi semantic tắt). Cùng `q/scope/limit` + cùng snapshot → **cùng mảng `tags`/`items`** ở `semantic=0` và `semantic=1`. `/suggest` `limit ∈ {5, 8, 12}`, mặc định 8 (`< 768 px` gửi 5); khác → `400 invalid_request`.

| scope · mode | limit | `tag_max` | `lex_max` | `near_max` | Recent: tag / item |
|---|---|---|---|---|---|
| all · prefix/full | 5 | 2 | 4 | 1 + phần lexical thiếu, tối đa 2 | 2 / 3 |
| all · prefix/full | 8 | 3 | 6 | 2 + phần lexical thiếu, tối đa 3 | 3 / 5 |
| all · prefix/full | 12 | 4 | 9 | 3 + phần lexical thiếu, tối đa 4 | 4 / 8 |
| item | 5 / 8 / 12 | 0 | 4 / 6 / 9 | như all (chỉ item) | 0 / `limit` |
| tag | 5 / 8 / 12 | = `lex_max` | 4 / 6 / 9 | như all (chỉ tag) | `limit` / 0 |

Công thức `internal/suggest/quota.go`: `tags_used = min(tag_hits, max(tag_max, lex_max − item_hits))`; `items_used = min(item_hits, lex_max − tags_used)`; `near_used = min(near_hits_sau_dedup, near_max, limit − tags_used − items_used)`. Recent không có near, không gọi provider. Thứ tự hiển thị cố định Tags → Items → Gần nghĩa (§6.4); recent "Gần đây" (item) → "Tag hay dùng" (mockup quyết). Lexical đủ `lex_max` không bao giờ nhường slot cho near. `/search` (BE-12): `limit ∈ {20, 50}` mặc định 20; phân trang theo scope — `scope=item`: chỉ item, keyset `SearchItemsLexicalPage`; `scope=tag`: chỉ tag, `limit` tag mỗi trang, keyset `SearchTagsLexicalPage` cùng ranking mục 2.3 (`tier, score, last_used_at, item_count, id`); `scope=all`: trang item theo keyset, `tags` chỉ trang đầu (≤ 5, không phân trang tag). Cursor mang `kind` (`item|tag`) và chỉ hợp lệ cho đúng scope/kind đó. `near` chỉ trang đầu (≤ 5, sau lexical).

### 2.7 Quyền riêng tư query và cache key (D1, advisor-dec-243)

- `q` không vào access log/metric label (giữ `middleware.go`), problem detail, audit, Sentry/console, URL/history web (kết quả trong listbox, không route `/app?q=`), storage trình duyệt, cursor. ### 2.12 Provider (`internal/embedding`)

```go
type Provider interface {
    Name() string         // "openai_compat" | "tei" | "noop"
    Model() string        // "openai_compat/<EMBEDDING_MODEL>" | "tei/<model_id>"
    ModelVersion() string // openai_compat: "dims=1024;instr=<sha8>"; tei: "<model_sha>;qp=<sha8>;dp=<sha8>"
    Dims() int
    MaxBatch() int        // 64
    EmbedDocuments(ctx context.Context, inputs []string) ([][]float32, error)
    EmbedQuery(ctx context.Context, q string) ([]float32, error)
}
```

- **`noop`**: không bao giờ được gọi; deployment = semantic unavailable (bỏ câu "vector 0" của §4.4: cosine với vector 0 là NaN).
- **`openai_compat`** (`openai_compat.go`): `POST {EMBEDDING_BASE_URL}/embeddings`, `Authorization: Bearer`, `{model, input, dimensions, encoding_format:"float"}`; query = `"Instruct: " + instruction + "\nQuery:" + q`, document không prefix. Sắp theo `data[].index`, đòi đúng `0..n-1`, `len == dims`, không NaN/Inf, norm > 0; L2-normalize trong Go (float64). Sai → `ErrBadResponse`.
- **`tei`** (`tei.go`): boot đọc `GET {TEI_URL}/info` → `Model()`/`ModelVersion()`; `POST /embed {inputs, normalize:true, truncate:true}`; vẫn kiểm dims + L2-normalize ở Go. Prefix qua `TEI_INPUT_PREFIX_QUERY`/`TEI_INPUT_PREFIX_DOCUMENT`.
- **HTTP client chung**: không follow redirect (như `auth/service.go:128-130`); `DialContext` kiểm IP đích mỗi lần dial (chặn DNS rebinding); body đọc tối đa 4 MiB. **Rule URL** (`urlrule.go`, config validate + dialer): `https://` bất kỳ; `http://` chỉ khi mọi IP đích thuộc loopback, RFC 1918, `100.64.0.0/10`, `fc00::/7`; áp cho `EMBEDDING_BASE_URL`, `EMBEDDING_SHADOW_BASE_URL`, `TEI_URL` ở mọi `APP_ENV`.
- **Danh tính (M1, BE-1/BE-13/BE-14, FS-23):** kiểu nằm ở package lá `apps/api/internal/embedding/embedid/identity.go` do **Task 1** tạo ở W0: `type Identity struct{Provider, Model, ModelVersion string; Dims int; QueryPrefix, DocPrefix, Preprocessing string}` + `func (Identity) Key() string` (mã hoá không nhập nhằng cả bảy trường, có tách độ dài) + `type CalibrationLookup func(Identity) (minCos float64, reportPath string, ok bool)` (chữ ký chốt ở Task 1 — N3/FS-32; Task 6 `Bootstrap`, wrapper Task 11a và `calibration.go` Task 7 đều theo đúng kiểu này). Task 5 và Task 6 cùng import, không lane nào định nghĩa kiểu danh tính thứ hai.
- **Client set + khớp danh tính (BE-1, `clientset.go`)**: `ClientSet` (client từ `EMBEDDING_*` và `EMBEDDING_SHADOW_*`, mỗi client mang một `embedid.Identity`) `.Match(id embedid.Identity)` chỉ trả client khi `client.Identity.Key() == id.Key()` (**cả bảy** trường), kiểm **trước** mọi lời gọi mạng. Cùng model ID nhưng khác revision (`ModelVersion`) hoặc khác prefix document → không khớp → query `degraded` (`generation_unconfigured`), job `JobSnooze(5m)`; không bao giờ gọi provider hay upsert vào generation cũ.
- **Bí mật/log**: `EMBEDDING_API_KEY` chỉ từ env; `Redacted()` chỉ ghi `embedding_api_key_set`. Log provider chỉ `provider`, `op`, số input, latency, `error_class`, HTTP status; không input, `q`, body response, URL đầy đủ, header.
- **Breaker** (`breaker.go`, một breaker/provider/process): API (query) một lỗi timeout/5xx/429/network/bad_response → mở 60 s; half-open đúng **một** request thử, request khác vẫn lexical. Worker (document): 3 lỗi liên tiếp → mở 60 s; job gặp breaker mở → `river.JobSnooze(còn lại + jitter 0–10 s)`; 429 có `Retry-After` → snooze tới `min(Retry-After, 1 h)`. Không retry trong cùng request query.
- **Canary** (`canary.go`, ADR 0004): job `embedding_canary` (boot + mỗi giờ) embed 8 chuỗi hằng trong code, so với `canary` của hàng generation (lần đầu thì ghi); cos < 0.99 → `embedding_canary_drift_total` + log warn; không tự cutover.

### 2.16 Truy vấn vector exact/ANN (Task 14)

- `SEARCH_EXACT_MAX_VECTORS` áp riêng item/tag. **Một** phép đếm có trần (BE-2): `SELECT count(*) FROM (SELECT 1 FROM <tbl> WHERE user_id=$1 LIMIT $fallback_max+1) s` với `$fallback_max = SEARCH_EXACT_FALLBACK_MAX_VECTORS` (≥ exact max, mục 2.13) (index-only trên PK, một partition); cùng số đếm so với **cả hai** ngưỡng. `SEARCH_EXACT_MAX_VECTORS=0` (benchmark luôn ANN) vẫn tôn trọng trần fallback. Tenant whale 100k (count = trần + 1) không bao giờ đi exact fallback. Không cache số đếm ở MVP (chỉ thêm cache 60 s nếu benchmark buộc).
- **Exact** (`count ≤ max`): tiền chọn tenant qua PK trong `MATERIALIZED` CTE (chặn planner dùng HNSW), join `item`/`tag` sống, `1 − (e <=> q) ≥ min_cos`, `ORDER BY dist, id`.
- **ANN** (`count > max`): một read-only tx, một `pgx.Batch`: `SET LOCAL hnsw.iterative_scan`, `hnsw.ef_search`, `hnsw.max_scan_tuples`, `statement_timeout = <budget nhánh>`, rồi candidates qua HNSW trong `MATERIALIZED` CTE (`WHERE user_id=$1 ORDER BY e.embedding <=> $2 LIMIT $k`), join sống, lọc ngưỡng, **sort lại** `dist, id` (bắt buộc với `relaxed_order`).
- **Underfill**: candidate trước lọc ngưỡng < K **và** budget còn ≥ `SEARCH_VECTOR_FALLBACK_MIN_BUDGET` **và** `count ≤ SEARCH_EXACT_FALLBACK_MAX_VECTORS` → exact trong budget còn lại; không thì trả phần đã có. Không gọi ANN là exact, không hứa đủ K. Hash partition chỉ cho pruning: trong HNSW, filter user vẫn là post-filter — benchmark ép ca tenant trung bình chung partition với whale.
- API `store.VectorSearch(ctx, pin, userID, corpus, qvec, k, deadline) ([]Hit, PathStats)`; Hit có `cos` chỉ để `semantic` sắp vùng near.
